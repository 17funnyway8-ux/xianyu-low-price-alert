## 3. 亮点与缺陷清单

### 3.1 真正值得肯定的点（具体到函数）

1. **`XianyuClient._sign` + `search`：协议层零失误**（R-L186-194 / R-L211-277）
   - 签名串 7 段拼接与 `json.dumps(..., separators=(",",":"), ensure_ascii=False)` 的字节一致性，是闲鱼 mtop 验签最容易翻车的地方；作者做对了，且 14/14 实证校验零偏差（🔵）。
2. **`parse_price`：领域鲁棒解析**（R-L113-133）
   - 「万」换算 + 「面议/电议/私聊/咨询」过滤 + 货币符号/千分位清洗，一函数覆盖闲鱼价格文案的脏数据；且只捕获 `ValueError`（D-L494），异常面收得比骨架标注更窄。
3. **去重状态机**（`dedup_key` + `monitor` 四条件短路，R-L472-479 / R-L535-548）
   - 有 item_id 用 item_id、无则 `title|seller|price_text` 兜底，JSON 持久化——简单、正确、可解释。
4. **`monitor` 的可中断休眠 + 轮级容错**（R-L555-569，D-L2548-2563）
   - `sleep(min(5, interval-slept))` 分片睡眠 + 每片前检查 `stop_event`，停止延迟 ≤5s；单轮异常只记日志不杀循环、失败轮不写去重——「宁可漏一轮也不崩」的意图是正确方向。
5. **GUI 线程模型**（R-L687-699）
   - `queue.Queue` + `root.after(200ms)` 桥接，monitor 跑 daemon 线程——规避了 tkinter 跨线程操作控件这一经典崩溃源。

#### 缺陷 #1 成因链条展开（toast 缺陷）

```
打包清单漏 win11toast/plyer（归档 PYZ 全树搜索零命中，🟢 确证）
   │
   ▼
运行到 Notifier._toast → `from win11toast import toast`（R-L387 / D-L1510）
   │
   ▼
ImportError（模块不存在）
   │
   ▼
被 `except Exception:` 捕获（R-L390 / D-L1528）→ 降级分支
   │
   ▼
`from plyer import notification`（R-L392 / D-L1537）→ 同样 ImportError
   │
   ▼
被第二个 `except Exception: pass` 吞掉（R-L394-395 / D-L1553-1560）
   │
   ▼
_notify 继续执行 sound/bark/webhook（R-L369-374），本通道静默失败
   │
   ▼
而 `toast` 默认值为 true（R-L87，DEFAULT_CONFIG）→ 每次提醒都走这条必死路径
   │
   ▼
用户视角：设置里开着「桌面弹窗」，实际永远看不到弹窗、也看不到任何错误
```

**本质**：这不是单个 bug，而是**三层系统性问题的叠加**——① 打包流程未验证真实导入路径；② 异常处理策略把「失败」与「静默」划等号；③ 默认配置开启了一个从未被验证过的功能。三层任何一层做对，缺陷都不会以「无声」形式存在。

### 3.3 客观性校准（避免误判）

- 全文以「能用的小工具」为基准评分，未用企业级标准（无 CI/无签名/无文档等在企业级是硬伤，在此仅轻微扣分）。
